# 六腳懸空低速控制調整（2026-09-08，第二輪）

使用者確認每隻腳在完全懸空、不碰地時都有卡頓。本次調整共用的 Calibration、Standing、Manual、Tripod 控制公式；40 的摩擦補償是試調起點，並非逐腳量測出的精確值。總 PWM 命令上限仍為 80。

## 為什麼改控制公式

21:59 的 L2 日誌已使用上限 80、20 ms 速度濾波及 250/s 的出力變化限制。
在 5°/s 勻速段，命令約 28～53；49 筆日誌中有 19 筆原始速度接近零。
位置誤差修正原為 0.35 PWM/count，1°（153.6 counts）就會改變約 53.76 的命令。
軸一追上目標就容易大幅收力。這與起轉摩擦及控制延遲共同形成走走停停的假設相符；日誌本身不能排除驅動器或機械因素。

## 本次共用參數

| 參數 | Calibration／Standing／Manual 原值 | Tripod 原值 | 本次懸空試調 |
|---|---:|---:|---:|
| `kp` 位置誤差修正 | 0.35 | 0.38 | 0.08 |
| `kd` 速度誤差修正 | 0.002 | 0.003 | 0.006 |
| `k_ff` 速度前饋 | 0.02 | 0.005 | 0.005 |
| `friction_pwm` 摩擦補償 | 0 | 0 | 40 |
| `friction_velocity_counts_s` 接近零速的補償退場範圍 | 未使用 | 未使用 | 153.6（約 1°/s） |
| `max_pwm` 出力命令上限 | 80 | 80 | 80 |

控制命令為：

```text
kp × 位置誤差 + kd ×（目標速度 − 控制用速度）
+ k_ff × 目標速度 + friction_pwm × tanh（目標速度 / friction_velocity_counts_s）
```

位置與速度使用 encoder counts、counts/s；最後仍套用各模式的輸出限制。
`tanh` 使補償隨目標方向連續變化，接近停止時逐漸退到零。它不是「PWM 至少要 40」的限制，控制器仍能減力、反向修正和停止。Hall 觸發後的停止、停用腳、握手用零出力命令均走原本的停止／停用路徑。

以 5°/s 來看，舊速度前饋只有約 15.36；新速度前饋加摩擦補償約 43.84，另加位置與速度修正。位置誤差每 1° 的修正則從約 53.76 降為 12.29。
Calibration 的 36°/s 基本命令由舊前饋約 110.59（尚未加誤差就超過 80）改為約 67.65。
Standing 到位保持使用不高於 0.1 的位置修正增益，目標速度為零時不加摩擦補償。

## 設定與驗證

權威設定仍在 `/home/jetson/redrhex_site/rinbo_fsm_disabled_leg.yaml`。
Manual 使用該檔 Standing 的參數。原本沒有新增欄位的舊設定仍能讀取，保留舊增益及零摩擦補償；這次現場設定與新版 `disabled_leg_template.yaml` 明列新參數。

管理命令（不初始化 ROS、不送動作）：

```bash
ros2 run rinbo_fsm rinbo_legs tune-motion 0.08 0.006 0.005 40 153.6
```

命令確認沒有動作程序、取得設定鎖、驗證所有參數後，原子更新三個模式並遞增版本，使舊校正／Standing 紀錄失效。同值重複執行不改版本；屏蔽腳、PWM 上限、電流電壓與通訊保護設定不隨調參改動。

新增測試覆蓋零速、正反轉、畸形參數、停用與限制路徑、共用設定載入，以及包含摩擦與延遲的簡化模型。模型用來驗證走走停停的機制，**不能證明實機已順暢，也不是馬達辨識結果**。

重新啟動 `./robot.sh` 後，以原本的 L2、5°/s、3 秒先比較。新參數使舊校正失效，會重新校正。日誌應顯示：

```text
Motion effort: kp=0.0800 kd=0.0060 k_ff=0.0050 friction_pwm=40.0 fade_counts_s=153.6
```

所有腳的共同初值仍需逐腳實測；若有某腳不順，應使用它自己的速度與出力日誌調整。現有 sim-to-real `rinbo_ros` adapter 使用另一條速度到 PWM 換算路徑，本次沒有把懸空 PD 參數直接當成策略控制器已驗證的參數。
