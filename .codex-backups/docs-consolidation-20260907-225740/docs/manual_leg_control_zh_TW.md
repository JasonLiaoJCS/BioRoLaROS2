# 用一個終端機控制每隻腳

已依你提供的 **R-Slip v6.6** 整合 sbRIO → Bridge → 電源 → 校正流程。
位址已填好：sbRIO `192.168.30.254`、Jetson `192.168.30.8`、ROS domain `99`。

## 打開操作台

在 **Jetson** 終端機貼上：

```bash
cd /home/jetson/rinbo_ros_ws
./robot.sh
```

啟動選單不會上電，日常依序選 **1 → 2 → 3**。
本操作台與 Windows 啟動器擇一使用，不要同時操控。

## 不知道下一步做什麼，或數字怎麼填

**直接在主選單輸入 `h`**，就會看到每一步的白話說明。
想從簡單設定開始，**輸入 `r`**：程式選一隻目前可用的腳，套用「從現在小轉 +5°」的入門範例。
這一步只存設定，之後仍要選 `3`、確認並輸入「開始」才執行。

填數字時，畫面會同時寫出用途、入門建議、可填範圍，以及 **直接 Enter 會採用的值**。
Enter 會沿用顯示值，可能是你以前改過的設定；要回到入門範例請用 `r`。

| 數值 | 入門起點 | 白話意思 |
|---|---|---|
| 保持／勻速時間 | 3 秒 | 到位後保持多久，或固定速度轉多久；另加對齊與加減速 |
| 速度上限 | 10 度／秒 | 目標速度最多到多少；每隻腳的旋轉速度另填 |
| 小轉一下的角度 | +5 度 | 從現在再轉 5 度；-5 是反方向 |
| 按速度旋轉 | 5 度／秒 | 固定速度轉一整圈約 72 秒 |
| 起始相位 | 單腳先用 0 度 | 先對齊再转；兩腳 0、180 是相差半圈，可能先大幅對齊 |
| 逐腳動作出力上限 | 20 | 限制驅動出力，不是速度、伏特或百分比 |
| 加速度 | 10 度／秒² | 目標速度改變多快；從 0 到 10 度／秒至少約 1 秒 |

「移到角度」以校正零點為基準，填 5 不等於從現在只轉 5 度；第一次試動建議選「小轉一下」。
上述是程式的入門設定，是否到位仍由回讀檢查。可填範圍只是程式允許的範圍，先從入門值開始。
這些動作限制用於校正後的逐腳動作；校正使用現場設定，會涉及全部未禁用主馬達與相關伺服。

## 選 1：把通訊開起來

**同一個視窗輸入 sbRIO 的 admin 密碼即可。** 密碼輸入時不會顯示，也不會儲存。
第一次 SSH 連線可能要求確認主機指紋；使用正常 OpenSSH 提示，不略過身分驗證。

程式自動處理：

```text
檢查 Jetson 網卡 → SSH 登入 sbRIO → 設定函式庫路徑與 IP
→ 核對 FPGA 檔案 SHA-256
→ 啟動 core，確認 50051 監聽
→ 啟動 FPGA driver，確認 Session opened (Success)
→ 啟動 Jetson Bridge → 確認 motor/state 與 power/state 都有新資料
```

**看到「通訊就緒」才算成功；本次還沒有上電。**
已在跑且設定相符的服務會沿用。重複選 1 不重啟服務、不重新上電、不重新校正。
既有 driver 先核對程序身分、IP、工作目錄，再以實際 ROS 回讀確認通訊。

| 畫面錯誤 | 要處理什麼 |
|---|---|
| Permission denied | sbRIO 登入未通過，使用 sbRIO 的 admin 密碼 |
| CORE_LOCAL_IP／CORE_MASTER_ADDR 不符 | sbRIO 上仍有使用舊 IP 的程序，先處理舊通訊 |
| FPGA SHA-256 不符 | FPGA 檔案不符 v6.6，不能跳過 |
| Open Failed／-63101 | FPGA 開啟失敗，先處理 sbRIO 問題 |
| 50051 拒絕連線 | core 未正常提供通訊服務，查看 sbRIO 日誌 |
| Bridge 已開但沒有新回讀 | 檢查 driver，不能繼續上電 |

## 選 2：設定這次怎麼動

例如讓 L2 小轉一下：

| 畫面問什麼 | 填入 |
|---|---|
| 要控制哪些腳 | `L2`；多隻可填 `L2 R2` |
| 保持／勻速時間 | 先按 Enter，使用 3 秒 |
| 最大速度 | 先按 Enter，使用 10 度／秒 |
| 這隻腳怎麼動 | 選 `1`：小轉一下 |
| 從現在轉幾度 | `5`；反方向填 `-5` |

**「小轉一下 +5°」是從現在再轉 5°。** 例如目前在 170°，目標是 175°。

每隻腳能各自選：

- **小轉一下：** 從現在的位置轉指定角度，限制 ±30°。
- **移到角度：** 移到相對校正零點的角度，可能大幅轉動。
- **按速度旋轉：** 每秒轉幾度，負數為反方向。
- **按相位旋轉：** 先對齊相位再轉；180° 是半圈。想維持固定相位差，速度須相同。

未選的主馬達停用。禁用名單直接讀 Orin 現場設定，禁用腳不能選，不會自動解除屏蔽。

## 選 3：確認後執行

先可靠固定機身、讓腳懸空，清空轉動範圍並準備實體急停。
程式列出動作與校正範圍。**輸入「開始」才上電與動作；直接 Enter 取消。**

首次上電依 v6.6 接好：

```text
確認沒有其他馬達控制程式 → 全部關電並確認
→ Digital → Signal → 確認馬達輸出=false、命令發布者=0
→ Relay（18–30 V、未禁用腿電流小於 3 A、連續 3 筆有效回讀）
→ 校正完成並確認馬達停用 → 執行你的逐腳動作
→ 確認馬達停用，關 Relay、保留感測器供電
```

感測器已保持供電時，不會重做 Off／Digital／Signal；Relay 已開時只核對回讀，不重送上電。
每個電源指令最多等 8 秒尋找 Bridge，找到就繼續，不反覆上電重試。

若顯示「正在辨識 Bridge 的資料來源」，是校正程式自己的 ROS 連線仍在準備，最多等待 8 秒。
這段等待尚未建立馬達命令發布者；來源確認後，才開始原有的回讀與握手檢查。
若持續無法辨識、出現錯誤來源或重複發布者，仍會停止並嘗試關電。

**每次新開操作台，第一次執行會校正全部未禁用主馬達及相關伺服，不只這次選的腳。**
禁用主馬達不代表同側伺服斷電，故障部件需依現場方式隔離。
同一個操作台內，校正有效且感測器供電與回讀持續正常，就可沿用校正。
全部關電、回讀中斷或設定變更後需重新校正。

保持／勻速時間另外加上對齊、加減速與收尾時間。沒到位或跟不上目標時先處理原因，不要直接加大出力。

## 停止與重試

| 操作 | 結果 |
|---|---|
| 動作中按 Ctrl+C，或輸入 `s` 再 Enter | 停止本次動作，嘗試全部關電，保留通訊 |
| 正常完成 | 關馬達電源、保留感測器，方便下一次調整 |
| 選 `4` | 全部關電，保留通訊 |
| 選 `0` | 確認關電 → 停本工具的 Bridge → 停本工具的 driver／core → 離開 |

失敗後先處理原因，再由你選 3 重試，程式不自動重跑。
沿用外部啟動的通訊程序時，本工具不會停止它們，最後由原啟動器完成停止。
關電未知或停止未完成，不能當成成功；使用實體急停／切斷動力電源，保留通訊供排查。
停用驅動不會鎖住腳，也不保證立即消除慣性。

本工具採用 v6.6 **Part B 的啟動與檢查順序**，並保留逐腳測試功能。
Windows 的 Standing／Tripod 與「失敗後仍保留 Relay」局部重試，仍由原 Windows 啟動器負責。
本工具失敗會嘗試關電，不將失敗動作記成成功。

## 日誌、演練與更新

- Jetson 日誌：`~/.local/state/rinbo_control/logs/`。
- sbRIO 日誌：`/home/admin/.local/state/rinbo-control/<本次編號>/`，啟動時會印出完整路徑。
- Jetson 程序紀錄：`~/.local/state/rinbo_control/sbrio-session.json`，用於下次核對 sbRIO 程序，不含密碼。不要刪除來繞過停止。
- 選 `5` 看狀態；選 `6` 改 IP。有舊位址的通訊紀錄時，先用原位址完成停止。
- `./robot.sh --demo`：不連線、不上電的選單演練。
- `./robot.sh --check`：只檢查安裝，不連設備。

本次更新需編譯；之後改角度、速度不需重編：

```bash
cd /home/jetson/rinbo_ros_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
CMAKE_BUILD_PARALLEL_LEVEL=2 MAKEFLAGS=-j2 colcon build --packages-select rinbo_fsm rinbo_control redrhex_lowlevel_bridge --parallel-workers 1
```
